IMPORTANT FIX: Output Extraction & Comparison
==============================================

PROBLEM IDENTIFIED
-----------------

The original scripts assumed program output would always be in a tuple format like:
  '#(8571429 1428571 1071429 535714 25714287 #t 17142858)

However, programs can output various formats:
  • Simple numbers: 500000500000
  • Multi-line text
  • Other data structures

Additionally, the scripts were comparing raw outputs including timing data,
which could cause false mismatches.

SOLUTION IMPLEMENTED
-------------------

Both scripts now use an improved output extraction method that:

1. **Filters out ALL timing data** before comparison:
   - itertime: lines
   - ITER TIMES: arrays
   - ITERS, SIZE, BATCHTIME, SELFTIMED
   - Running pass/program headers
   - End markers
   - Empty lines

2. **Extracts pure program output** regardless of format:
   - Tuple outputs: '#(...)
   - Number outputs: 500000500000
   - Multi-line outputs
   - Any other format

3. **Normalizes whitespace** for reliable comparison:
   - Handles different line endings
   - Ignores extra spaces
   - Compares semantic content

CHANGES MADE
-----------

### Python Script (gibbon_benchmark.py):

1. Added new function `extract_program_output()`:
   - Uses regex patterns to filter out timing lines
   - Preserves all non-timing output
   - Returns normalized result

2. Updated `parse_benchmark_output()`:
   - Now calls extract_program_output() instead of regex for tuples
   - Handles any output format automatically

3. Enhanced `compare_outputs()`:
   - Normalizes whitespace before comparison
   - More robust matching

4. Improved report generation:
   - Shows detailed mismatch information
   - Displays both outputs when they differ

### Bash Script (gibbon_benchmark.sh):

1. Rewrote `extract_output()`:
   - Uses grep with extended regex to filter timing lines
   - Normalizes whitespace
   - Returns clean program output

2. Enhanced `compare_outputs()`:
   - Normalizes whitespace for both outputs
   - Shows actual outputs when they differ
   - Better error reporting

3. Updated report generation:
   - Shows mismatch details
   - Points to full output files for investigation

TECHNICAL DETAILS
----------------

### Extraction Algorithm:

1. Split output into lines
2. For each line, check against exclude patterns:
   - Line starts with timing keywords
   - Line is a benchmark header
   - Line is "End" marker
   - Line is empty/whitespace only
3. Keep all other lines (the actual program output)
4. Join kept lines and normalize whitespace

### Comparison Algorithm:

1. Extract output from both AoS and SoA runs
2. Normalize whitespace (collapse multiple spaces, trim)
3. Compare normalized strings
4. Report match/mismatch with details

### Regex Patterns Used:

Python:
- r'^itertime:'
- r'^ITER TIMES:'
- r'^ITERS:'
- r'^SIZE:'
- r'^BATCHTIME:'
- r'^SELFTIMED:'
- r'^Running pass'
- r'^Running program'
- r'^Running the Compiler'
- r'^End$'
- r'^\s*$'

Bash:
- '^(itertime:|ITER TIMES:|ITERS:|SIZE:|BATCHTIME:|SELFTIMED:|Running pass|Running program|Running the Compiler|End$|^[[:space:]]*$)'

TROUBLESHOOTING
--------------

If you encounter issues:

1. **Outputs not matching when they should:**
   - Check for hidden characters or encoding issues
   - Review the full output files in benchmark_output/
   - Run diff manually on the output files

2. **Timing data appearing in extracted output:**
   - This shouldn't happen with the new code
   - Report as a bug if you see this

3. **Empty extracted output:**
   - Program may not be producing output
   - Check if program runs successfully
   - Review raw output in benchmark_output/*.output.txt
