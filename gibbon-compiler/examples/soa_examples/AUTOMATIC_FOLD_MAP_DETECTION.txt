GREAT NEWS!
===========

The script now AUTOMATICALLY detects fold vs map classification from your
existing print statements! No need to add annotations!

HOW IT WORKS
============

The script parses your print statements that look like:

  printsym (quote "Running pass SumArea (fold): ")
  printsym (quote "Running pass scaleLayout (map): ")
  printsym (quote "Running pass Find nearest Neighbour (fold like): ")

Pattern: "Running pass <PassName> (<type>): "

Automatically extracts:
  ✓ Pass name: SumArea, scaleLayout, Find nearest Neighbour
  ✓ Pass type: fold, map, fold like

WHAT YOU NEED TO DO
===================

NOTHING! Just run:

  ./gibbon_benchmark.py --generate-paper

The script will:
1. Read your .hs files
2. Find all printsym statements
3. Parse pass names and types
4. Generate tables with fold/map classification
5. Generate figures separated by fold/map

PASS NAME MATCHING
==================

The script is smart about matching pass names!

It tries multiple variations:
  ✓ Exact match: "SumArea"
  ✓ Without spaces: "findmaxBottom"
  ✓ Lowercase: "sumarea"
  ✓ Without "Pass" suffix: "instCount" (if benchmark shows "instCountPass")

So even if your print statement says "Sum Area" and the benchmark
reports "SumAreaPass", it will still match! ✓

SUPPORTED TYPE KEYWORDS
=======================

The script recognizes:
  ✓ "fold" → classified as fold
  ✓ "map" → classified as map
  ✓ "fold like" → classified as fold
  ✓ "fold-like" → classified as fold
  ✓ "map like" → classified as map

Anything else → shows as "?" in tables

TROUBLESHOOTING
===============

Issue: Pass shows as "?" in table
----------------------------------
Check: Does your print statement have (fold) or (map)?

Example:
  ✗ printsym (quote "Running pass SumArea: ")
  ✓ printsym (quote "Running pass SumArea (fold): ")

Issue: Pass type not detected
------------------------------
The script will print a note if it can't parse a file:
  "Note: Could not parse programs/AoS/DomTree.hs: ..."

Check file is readable and has correct syntax.

Issue: Want to verify what was detected
----------------------------------------
Run with verbose output (coming soon) or check the tables -
if Type column shows F or M, it was detected correctly!
