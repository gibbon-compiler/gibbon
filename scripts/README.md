# CI Workflow Management

## haskell-ci.yml Regeneration

The `haskell-ci.yml` workflow is auto-generated by the `haskell-ci` tool, but we need to post-process it to avoid duplicate CI runs.

### Problem
- `haskell-ci` generates `on: [push, pull_request]` which causes duplicate runs on PR updates
- We need `push` to only trigger on `main` branch
- We need `concurrency` to cancel in-progress runs

### Solution
Use the helper script to regenerate and fix the workflow:

```bash
./scripts/regenerate-haskell-ci.sh
```

This script:
1. Runs `haskell-ci regenerate` to get the latest matrix configuration
2. Post-processes the generated file to add:
   - `push.branches: [main]` (not all branches)
   - `pull_request` (unfiltered)
   - `concurrency` group to cancel in-progress runs

### Manual Process (if script fails)
If the helper script doesn't work, you can manually:

1. Run `haskell-ci regenerate`
2. Edit `.github/workflows/haskell-ci.yml`:
   ```yaml
   on:
     push:
       branches:
         - main
     pull_request:
   concurrency:
     group: ${{ github.workflow }}-${{ github.ref }}
     cancel-in-progress: true
   ```

### Why This Approach?
- Keeps the benefits of `haskell-ci`'s matrix generation
- Fixes the duplicate runs issue at the workflow level
- Future-proof: works with any `haskell-ci` updates
- Documented for all contributors
